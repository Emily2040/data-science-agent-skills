# Messy Data Cleanroom

![Messy Data Cleanroom Hero Shot](assets/hero-shot.png)

![Messy Data Cleanroom Infographic](assets/reddit-infographic.png)

## Executive Summary

**Messy Data Cleanroom** is a portable, provider-neutral data science agent skill designed to design transparent, reversible cleaning plans for messy datasets without silently mutating evidence.

> **Core pain solved:** Cleaning decisions get buried in notebooks, making results impossible to audit or reproduce.

> **Proof callout:** Makes cleaning reviewable instead of magical.

## Research-Informed Design Standard

This skill follows reproducible data science and portable agent-skill standards:

- **Cookiecutter Data Science**: immutable raw data, clear artifact layout, and repeatable command entrypoints.
- **Kedro**: explicit input/output data contracts and modular workflow boundaries.
- **MLflow**: traceable parameters, metrics, provenance hashes, and governance-ready evaluation records.
- **Anthropic & Open Agent Skills**: concise `SKILL.md` frontmatter, progressive disclosure via `references/`, and deterministic local scripts in `scripts/`.
- **CfRR Reproducible Research**: deterministic verification, explicit uncertainty, and zero hidden state.

## Problem It Solves

Cleaning decisions get buried in notebooks, making results impossible to audit or reproduce. Without a structured gate, teams routinely discover `overwriting raw data` or `dropping rows without impact analysis` only after engineering effort or executive credibility has already been spent.

## What This Skill Should Do

- Transform a vague request into an explicit Messy Data Cleanroom decision with named owner, evidence, assumptions, and action threshold.
- Inspect local artifacts first: data extracts, schemas, notebooks, SQL, pipeline configs, model reports, tickets, and prior decisions.
- Separate mechanical checks from expert judgment so another reviewer can reproduce what was checked and what was inferred.
- Classify findings as stop, fix-first, monitor, accepted risk, or owner decision instead of producing generic advice.
- Preserve raw evidence and never silently mutate data, notebooks, model artifacts, or production configs.
- Return a decision artifact that can be handed to a data scientist, ML engineer, governance reviewer, or stakeholder without hidden context.

## Required Inputs

- raw dataset
- data dictionary if available
- analysis goal
- allowed transformation constraints

## Operating Workflow

1. Profile missingness, duplicates, outliers, types, formats, units, and conflicting records.
2. Separate factual corrections, normalization, exclusions, imputations, and unresolved anomalies.
3. For each proposed transformation, record rationale, affected rows, risk, and reversal method.
4. Prefer derived clean columns or versioned outputs over overwriting raw evidence.
5. Return a cleaning ledger and transformed-data acceptance criteria.

## Expected Outputs

- cleaning ledger
- transformation plan
- row impact summary
- reversal plan
- review questions

All outputs are delivered inside the eight-section decision contract: `Problem`, `Inputs`, `Checks performed`, `Findings`, `Decision`, `Risks`, `Next actions`, and `Artifacts`.

## Concrete Use Cases

- **Pre-commit readiness gate**: Run `scripts/profile_table.py` on `raw dataset` to produce a `cleaning ledger` before approving engineering scope.
- **Adversarial review**: Challenge a proposed `go` recommendation when `overwriting raw data` or `dropping rows without impact analysis` is suspected in `data dictionary if available`.
- **Cross-team handoff**: Generate `transformation plan` and `review questions` so ML engineers, governance reviewers, or downstream agents can act without re-running discovery.
- **Regression audit**: Score completed review checklists with `scripts/checklist_score.py --strict` inside CI to prevent unverified artifacts from shipping.

## Red Flags

- overwriting raw data
- dropping rows without impact analysis
- unit conversion not documented
- outlier removal tied to desired result
