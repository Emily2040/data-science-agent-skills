# Drift Monitor Designer

![Hero shot](assets/hero-shot.png)

## What This Skill Solves

Design drift monitoring for production models and data products across data, concept, performance, and operational signals.

Pain point: Models degrade silently because teams monitor uptime but not input, label, behavior, or outcome change.

Why it matters: Monitoring must match label delay, business risk, retraining options, and alert ownership.

## When To Use It

Use `$drift-monitor-designer` when the task is to design drift monitoring for production models and data products across data, concept, performance, and operational signals. It is built for judgment-heavy work where the agent must inspect evidence, name assumptions, and produce a decision-ready artifact.

## When Not To Use It

- Do not use this skill for generic spreadsheet editing, chart styling, or file conversion unless the data science decision workflow is the main task.
- Do not use it as a substitute for legal, medical, financial, or compliance approval.
- Do not use helper scripts as proof by themselves; scripts provide evidence checks, not full expert judgment.

## Inputs

- model purpose
- features
- prediction logs
- label availability
- risk tolerance
- owners
- retrain process

## Workflow

1. Classify drift risks: schema, distribution, relationship, concept, performance, and operational drift.
2. Choose monitors based on data type, label delay, and actionability.
3. Set thresholds, baselines, alert routing, and suppression rules.
4. Define retrain, rollback, investigation, or no-action playbooks.
5. Return a monitor design and incident response path.

## Outputs

- monitor catalog
- baseline definitions
- threshold plan
- alert ownership
- drift response playbook

Every final response should include: Problem, Inputs, Checks performed, Findings, Decision, Risks, Next actions, and Artifacts.

## Helper Scripts

Run scripts locally against explicit user-provided artifacts. They are support checks, not complete replacements for expert review.

- `scripts/quick_validate_skill.py .`: validate this standalone skill folder. Exit `0` means the package is structurally complete.
- `scripts/checklist_score.py checklist.json --strict`: score pass/partial/fail/blocker checklist JSON. Exit nonzero when strict mode finds anything below ready.
- `scripts/drift_probe.py --baseline baseline.csv --current current.csv --column score`: compare simple numeric mean shift and return stable/watch/investigate.

## Red Flags

- alerts with no owner
- thresholds copied from defaults
- label delay ignored
- no baseline window
- retrain triggered without evaluation
