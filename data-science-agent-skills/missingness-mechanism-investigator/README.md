# Missingness Mechanism Investigator

![Hero shot](assets/hero-shot.png)

## What This Skill Solves

Diagnose missing-data mechanisms and design imputation, exclusion, or sensitivity plans.

Pain point: Missing values are filled or dropped mechanically, creating bias and false confidence.

Why it matters: MCAR, MAR, and MNAR require different assumptions; the skill forces mechanism thinking before imputation.

## When To Use It

Use `$missingness-mechanism-investigator` when the task is to diagnose missing-data mechanisms and design imputation, exclusion, or sensitivity plans. It is built for judgment-heavy work where the agent must inspect evidence, name assumptions, and produce a decision-ready artifact.

## When Not To Use It

- Do not use this skill for generic spreadsheet editing, chart styling, or file conversion unless the data science decision workflow is the main task.
- Do not use it as a substitute for legal, medical, financial, or compliance approval.
- Do not use helper scripts as proof by themselves; scripts provide evidence checks, not full expert judgment.

## Inputs

- dataset
- analysis goal
- column meanings
- collection process
- known reasons for missingness

## Workflow

1. Profile missingness by column, row, group, time, and target relationship.
2. Classify likely mechanisms as MCAR, MAR, MNAR, structural missing, or unknown.
3. Identify whether missingness itself should be a feature, exclusion reason, or bias warning.
4. Recommend complete-case, imputation, indicator, model-based, or sensitivity strategy.
5. Return a missingness report with assumptions and impact on claims.

## Outputs

- missingness heat map summary
- mechanism labels
- imputation plan
- sensitivity plan
- claim limitations

Every final response should include: Problem, Inputs, Checks performed, Findings, Decision, Risks, Next actions, and Artifacts.

## Helper Scripts

Run scripts locally against explicit user-provided artifacts. They are support checks, not complete replacements for expert review.

- `scripts/quick_validate_skill.py .`: validate this standalone skill folder. Exit `0` means the package is structurally complete.
- `scripts/checklist_score.py checklist.json --strict`: score pass/partial/fail/blocker checklist JSON. Exit nonzero when strict mode finds anything below ready.
- `scripts/profile_table.py data.csv`: profile CSV columns, missingness, uniqueness, numeric ranges, and PII-name hints.

## Red Flags

- target-dependent missingness
- structural missing treated as random
- imputed identifiers
- dropped rows change population
- no collection-process explanation

## Validation

Run `python scripts/quick_validate_skill.py .` inside this folder. For script-backed checks, run the relevant script on local fixture data or user-provided artifacts. Validate the result against `references/acceptance-tests.md`.
