# Metric Design Review Board

![Hero shot](assets/hero-shot.png)

## What This Skill Solves

Review whether a chosen data science metric actually supports the decision, user outcome, risk, and cost tradeoff.

Pain point: Projects optimize metrics that look scientific but misalign with business impact or safety.

Why it matters: Metric design is a governance problem: success, guardrails, thresholds, and cost curves must be decided together.

## When To Use It

Use `$metric-design-review-board` when the task is to review whether a chosen data science metric actually supports the decision, user outcome, risk, and cost tradeoff. It is built for judgment-heavy work where the agent must inspect evidence, name assumptions, and produce a decision-ready artifact.

## When Not To Use It

- Do not use this skill for generic spreadsheet editing, chart styling, or file conversion unless the data science decision workflow is the main task.
- Do not use it as a substitute for legal, medical, financial, or compliance approval.
- Do not use helper scripts as proof by themselves; scripts provide evidence checks, not full expert judgment.

## Inputs

- decision context
- candidate metrics
- stakeholders
- false positive and false negative costs
- guardrails

## Workflow

1. Map metrics to the real decision and affected user or entity.
2. Separate primary, diagnostic, fairness, reliability, and guardrail metrics.
3. Review threshold effects, class imbalance, cost asymmetry, and gaming risk.
4. Check offline-online and proxy-outcome mismatch.
5. Return a metric board decision with acceptance and monitoring criteria.

## Outputs

- metric tree
- cost curve notes
- guardrail list
- threshold recommendation
- metric risk memo

Every final response should include: Problem, Inputs, Checks performed, Findings, Decision, Risks, Next actions, and Artifacts.

## Helper Scripts

Run scripts locally against explicit user-provided artifacts. They are support checks, not complete replacements for expert review.

- `scripts/quick_validate_skill.py .`: validate this standalone skill folder. Exit `0` means the package is structurally complete.

## Red Flags

- metric not tied to action
- proxy metric can be gamed
- threshold chosen after results
- guardrails missing
- average hides subgroup harm

## Validation

Run `python scripts/quick_validate_skill.py .` inside this folder. For script-backed checks, run the relevant script on local fixture data or user-provided artifacts. Validate the result against `references/acceptance-tests.md`.
