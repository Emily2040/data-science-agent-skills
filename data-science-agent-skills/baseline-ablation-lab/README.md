# Baseline Ablation Lab

![Baseline Ablation Lab Hero Shot](assets/hero-shot.png)

![Baseline Ablation Lab Infographic](assets/reddit-infographic.png)

## Executive Summary

**Baseline Ablation Lab** is a portable, provider-neutral data science agent skill designed to design honest baselines and ablations before complex models are accepted.

> **Core pain solved:** Teams ship complex models without proving they outperform simple, cheaper, or safer alternatives.

> **Proof callout:** Stops expensive complexity from hiding weak value.

## Research-Informed Design Standard

This skill follows reproducible data science and portable agent-skill standards:

- **Cookiecutter Data Science**: immutable raw data, clear artifact layout, and repeatable command entrypoints.
- **Kedro**: explicit input/output data contracts and modular workflow boundaries.
- **MLflow**: traceable parameters, metrics, provenance hashes, and governance-ready evaluation records.
- **Anthropic & Open Agent Skills**: concise `SKILL.md` frontmatter, progressive disclosure via `references/`, and deterministic local scripts in `scripts/`.
- **CfRR Reproducible Research**: deterministic verification, explicit uncertainty, and zero hidden state.

## Problem It Solves

Teams ship complex models without proving they outperform simple, cheaper, or safer alternatives. Without a structured gate, teams routinely discover `no naive baseline` or `single random seed` only after engineering effort or executive credibility has already been spent.

## What This Skill Should Do

- Transform a vague request into an explicit Baseline Ablation Lab decision with named owner, evidence, assumptions, and action threshold.
- Inspect local artifacts first: data extracts, schemas, notebooks, SQL, pipeline configs, model reports, tickets, and prior decisions.
- Separate mechanical checks from expert judgment so another reviewer can reproduce what was checked and what was inferred.
- Classify findings as stop, fix-first, monitor, accepted risk, or owner decision instead of producing generic advice.
- Preserve raw evidence and never silently mutate data, notebooks, model artifacts, or production configs.
- Return a decision artifact that can be handed to a data scientist, ML engineer, governance reviewer, or stakeholder without hidden context.

## Required Inputs

- task type
- dataset summary
- candidate model
- metric
- deployment constraints
- cost constraints

## Operating Workflow

1. Select task-appropriate naive, rule-based, statistical, and simple ML baselines.
2. Define ablations for features, model components, preprocessing, data volume, and inference cost.
3. Set metric and uncertainty reporting before running comparisons.
4. Identify complexity penalties: latency, maintainability, explainability, and monitoring burden.
5. Return a baseline and ablation matrix with accept/reject criteria.

## Expected Outputs

- baseline list
- ablation matrix
- complexity penalty table
- acceptance criteria
- report template

All outputs are delivered inside the eight-section decision contract: `Problem`, `Inputs`, `Checks performed`, `Findings`, `Decision`, `Risks`, `Next actions`, and `Artifacts`.

## Concrete Use Cases

- **Pre-commit readiness gate**: Run `scripts/ablation_delta_audit.py` on `task type` to produce a `baseline list` before approving engineering scope.
- **Adversarial review**: Challenge a proposed `go` recommendation when `no naive baseline` or `single random seed` is suspected in `dataset summary`.
- **Cross-team handoff**: Generate `ablation matrix` and `report template` so ML engineers, governance reviewers, or downstream agents can act without re-running discovery.
- **Regression audit**: Score completed review checklists with `scripts/checklist_score.py --strict` inside CI to prevent unverified artifacts from shipping.

## Red Flags

- no naive baseline
- single random seed
- improvement below uncertainty
- cost ignored
- feature ablations missing
